## Decisions

- **Account models:** the picker reads `dextoGateway.dextoModels` (`GET /v1/models` on the sign-in or `DEXTO_API_KEY`) when Dexto models are enabled. A failure to list them is logged, and the picker still offers the person's own models. Each account model is offered as `dexto-nova` with the gateway's model id.
- **Reasoning:** the options come from `getReasoningProfile` for the session's model. The current value is the session's variant, else the profile's default. Choosing the default stores no variant, as the TUI does. A model change resets reasoning, as core already does.
- **Key errors:** choosing a Dexto model first checks `canUseDextoProvider`, as the TUI does. Any switch, session start or session restore that fails with `API_KEY_MISSING` becomes `auth_required` naming the provider's environment variable, or `dexto login` for Dexto models. ACP clients show `auth_required` as something the person has to set up, not as a crash.
- **Saved preferences:** only `dexto acp` changes. Its bootstrap applies `applyUserPreferences` when setup is complete and no `--model` is given, the same rule the interactive CLI uses, and skips unreadable preferences the same way. `dexto run` is unchanged. `applyUserPreferences` now drops the agent's `apiKey` and `baseURL` when the saved provider differs, since they belong to the agent's provider; otherwise an `openai-compatible` agent with a saved Anthropic model failed validation.
- **Renamed tools:** the loader maps retired builtin tool names to their current ones in every `builtin-tools` entry and removes duplicates. Installed agents are copies made by earlier releases and are never re-synced, so the loader is the one place every command passes through.
- **`baseURL` on a provider change:** a `baseURL` belongs to the provider it was set for. Core used to carry it to any provider that accepts one, which sent a switch from a custom `openai-compatible` endpoint to Dexto models to that endpoint. The fix is in core's resolver, where the rule lives, so the TUI gets it too.
